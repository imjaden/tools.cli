2.1 站点状态页：数据源与更新节奏

状态页（/status.html，别名 /health.html）是本站唯一由自动探测写数据的页面，读法如下。

项 说明
数据是什么 每个公开页面与其宿主的可访问性（HTTP 状态、TLS 剩余天数）与更新时效（产物生成时间 / 预算），不含任何业务数据
怎么产生 每日两次在固定槽位探测 → 落快照 → 页面构建期内联；具体时刻与最近一次生成时间见页面与 JSON 里的时间戳（不是实时监控，两次采样之间不会变化）
条带怎么读 近 15 天、每天一格，取当日最差有效样本；90 天 / 30 天可用率为聚合数字；灰色 = 当日没有有效样本
四态含义 正常 / 部分降级 / 严重故障 / 未知。「部分降级」指单页或构建链某一项不达标，不等于站点不可用
有效样本 失败集中在探测侧（大面积同时不可达）时，该样本会被标记并排除，格子悬停可看到排除次数；单页失败照常计入，宁可误报不掩盖
机器面 站内 /status.json：总状态、逐组件状态、可用率、事件与计划维护、生成时间戳；页面与 JSON 同源
免责 状态页与被测站点同宿主 —— 宿主自身故障时以 GitHub 平台状态作旁证，不声称「实时自测」

加站规则：状态页只监测「有自己部署页面与域名」的站点；没有公网页面的本地/内网服务不纳入（探不到、也给不出对外状态）。

3. URL 与路由规范

  • slug 即规范址：/<slug>.html，一级扁平，不带目录层级。
  • 别名 = 静态跳转桩：/<alias>.html 内嵌 canonical 指向规范址 + meta refresh（无后端 302）。
  • canonical 唯一：每页与每个别名桩都指向规范址，verify 逐页断言。
  • 私有条目不落 dist：visibility: private（含全部 kind: cli）只出现在本地导航，线上恒 404。

4. 发布形态（class A–E）

形态 含义 判据
A 自包含：单文件，file:// 直开可用 三问全否
B 伴生同目录：需要同目录静态伴生文件 有同级 js / css / 数据文件
C 共享资产：依赖站点级资产目录（图标 / 字体 / 图片） 有跨目录 ../assets 类引用
D 后端增强：有同源后端调用，带静态兜底 页面含同源 api 请求，且清单里声明了降级说明
E 后端必需：无静态兜底 同上但未声明降级 ⇒ 不进清单

三问判据：① file:// 直开是否可用 ② 是否有同源后端调用 ③ 是否有 ../ 跨目录引用。

6. 公开面纪律（verify 逐条断言）

门户 HTML 必须含：id="detailPane" / var DETAIL_DATA / id="docsOverlay" / var DOCS_DATA /

var STATE_DATA / id="hfVersion" / var PAGE_MODE = "site"。

必须不含（正则）：本机绝对路径、内仓目录路径、构建产物目录、本地起服务命令、CL + 两位以上数字、私有工具复制入口、本地 favicon 兜底。

机制：本地专用代码包在 /__LOCAL_ONLY_START__/ … /__LOCAL_ONLY_END__/ 之间，门户构建时

_strip_local_only() 整段剥离并把详情分发器收敛为只调 renderDetailSite()。

7. 构建器 pages-manager 能力矩阵

子指令 作用 闸门

8. 发布 SOP（判据与时序详见主仓发布规范 §9）

git commit --only -- <paths>                           # 源仓先提交（水印要用这个 SHA）
python3 pages-manager build  --json      # 水印 = HEAD，内置 gitleaks
python3 pages-manager verify --json
python3 pages-manager publish --push     # 顺带重生成 index.html
git commit --only -- index.html                        # 若 publish 报「已同步重生成」
git push origin main

只有公开页面内容变了才动产物仓：源页 / 清单 / 构建器 / 共享资产 / 发布记录 / 伴生文件 → 要发布；

changelog / features / 测试 / 文档 / 其它 CLI → 只进源仓。

9. 幂等与三道闸门

  • 幂等红线：dist 不得含 HEAD 派生字段；站点发布记录手写（发布记录数据），不从产物仓

git log 派生 —— 否则每次 publish 都新增提交 ⇒ 产物内容变化 ⇒ publish 自激成提交循环。

  • 闸门：① 水印必须包含「构建器 / 清单 / 资产」最近一次提交（堵「先 build 后 commit」）；

② 发布记录最新版本 == site.version；③ publish 成功后自动 localnav。

10. 验收与回滚

grep -o 'build: index @ script-miner [0-9a-f]*' 构建产物目录/index.html
git -C 产物仓本地副本 log --oneline -1     # site@build: N 页 ← script-miner@<同 SHA>
curl -sS https://tools.cli.jaden.tech/ | grep -o 'build: index @ script-miner [0-9a-f]*'
curl -sS -o /dev/null -w '%{http_code}\n' https://tools.cli.jaden.tech/pages-manager.html   # 期望 404

GitHub Pages 构建耗时 60–90 s：publish 成功 ≠ 线上立刻更新，等水印到位再断言。

回滚 = 产物仓 git revert <site@build 提交> 后 push；源仓若也 revert，必须重新 build + publish，否则源与产物重新漂移。

12. 常见问题

  • 线上没更新？ GitHub Pages 还在构建（60–90 s）；先看首页水印 SHA 是否已变。
  • 某页打不开？ 可能在 denylist 或 visibility: private（永不发布）。
  • 在产物仓手动改了文案？ 下次 publish 会被整段覆盖 —— 必须回源仓改。
  • 发布被拒「落后于页面源」？ 顺序错了：先 commit 页面源 → 再 build → 再 publish。
  • 发布被拒「版本不一致」？ bump 了 site.version 却没在 发布记录数据 补对应条目。
  • 本地导航显示「落后」？ 页面源提交后没重跑 build / publish；跑一次 publish --push 即可（会自动重生成）。
